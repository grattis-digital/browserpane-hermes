# Compact MCP baseline — 2026-09-06

[Machine-readable evidence](compact-mcp-2026-09-06.json) records raw workflow
totals, median/p95, original report hashes and exact compact-engine file hashes.
Reports were generated by this reproducible harness, not a model call. Baseline
runs preceded the final compact-only adapter and shutdown-cleanup refinements;
the pinned legacy server and fixture action/state checks were unchanged.

Same Apple M4 Pro / ARM64 macOS, Node 26.7.0, fresh sandboxed headless Chromium
146.0.7680.0. Each mode ran sequentially with 2 warmups and 12 measured trials.
Both backends ran as separate processes over real MCP HTTP, never simultaneously.
These are not Raspberry Pi, production X11, network-transfer or model benchmarks.

| Original Playwright MCP, separate | 8 | 3296.61 / 3316.48 ms | 51,512 | 12,038 |
| Original Playwright MCP, batched | 7 | 3262.63 / 3307.70 ms | 51,012 | 11,927 |
| Compact MCP, separate | 12 | 211.34 / 251.26 ms | 40,658 | 9,120 |
| Compact MCP, batched | 11 | 212.60 / 250.63 ms | 39,605 | 8,890 |

The matched workflow navigates to and observes a form, fills two text fields,
selects a plan, checks consent, clicks submit, verifies a real navigated receipt,
navigates to a table, observes **all 120 rows**, and reads an exact aggregate.
All final state/event checks passed. Fill/click/submit events were trusted;
selectOption events retain Playwright's synthetic semantics on both backends.
The original batched comparison uses its available `browser_run_code` batching,
not an artificially one-operation-only baseline. No API entry was substituted
with a direct browser action; independent browser checks are outside timings.

Matched batched result: **15.35× lower tool execution time**, **22.36% fewer JSON
result bytes**, and **25.46% fewer estimated output-text tokens** in this fixture.
The token column is the sum of `ceil(Unicode code points / 4)` per response, not a
tokenizer or billed-provider count. It excludes schema/request/model reasoning and
images. JSON bytes exclude MCP JSON-RPC/HTTP/TLS framing. Timing sums tool calls;
it excludes model inference, startup/session discovery and independent state checks.

Server tool descriptors fell from **29 / 17,354 bytes** to **5 / 5,114 bytes**
(70.53% fewer bytes), measured before Hermes filtering/rewriting. Existing Hermes
exclusions already hide two legacy tools, so this is not a claim about an exact
agent prompt or API bill.

## Tradeoffs and limits

- Complete table observation is **larger** with compact pagination: 28,909 bytes
  across five calls versus 24,488 bytes in one original response. Compact's small
  first page is not equivalent to a complete snapshot. Repeated ancestors,
  escaping and envelopes add cost. Use targeted reads when the task allows it.
- A targeted numeric table summary is much faster but slightly larger than an
  arbitrary-code aggregate: 8.67 ms / 414 bytes versus 1023.29 ms / 145 bytes
  (separate-mode medians). Compact includes explicit metadata and numeric caveats.
- Small form operations can cost more response bytes because compact returns
  explicit outcomes, safety tokens and a fresh view. The existing fill-form tool
  was already fast and emitted almost nothing; this is not a per-tool universal win.
- Batched and separate compact timings are effectively alike at this sample size;
  do not attribute the large gain to batching. Most gain removes measured legacy
  post-ready waits. Batching saves a form round trip/output; full-table pagination
  adds four calls in this deliberately equal-information workflow.
- The pinned current MCP returned submission responses about a second after the
  receipt was ready. Compact returned about 9–10 ms after readiness in the checked
  trials. Cross-process wall clocks are diagnostic only; primary timings use a
  monotonic clock. Small-sample p95 is noisy, not a service-level guarantee.
- No claims of anti-bot invisibility, vendor-wide superiority, paid-token savings,
  human-to-photon latency, or Pi speedup follow from these measurements.

## Semantic fast-path follow-up

The [curated fast-path result](semantic-fast-path-2026-09-06.json) exercises the
same synthetic 120-row table after adding immutable `state` projection. On the
same class of local machine, 20 cached continuation calls measured **0.772 ms
median / 1.056 ms p95** after the first Chromium capture. The complete five-call
table observation measured **27.69 ms median**, versus **47.34 ms** in the earlier
run: a directional 41.51% reduction while preserving all 120 row IDs.

This is not a paired run and uses five measured trials rather than twelve. The
whole mixed workflow measured 193.06 ms versus the historical 212.60 ms median;
the small unpaired samples do not isolate a whole-workflow speedup because
navigation/input dominate the other operations. Result
JSON for the complete table grew from 28,909 to 29,044 median bytes due to state
metadata. The sixth `pane_flow` tool raises descriptors from 5,114 to 7,558 bytes
(1,279 to 1,890 character-estimated tokens); that fixed schema cost must be
weighed against avoided model/tool turns in real agent evaluations.

Real disposable-Chromium qualification separately executes a two-stage flow
with three inputs in one MCP call, verifies both transitions, replays with zero
extra input, and rejects an ambiguous target before input. This proves browser
state and call-count behavior, not model latency, model success, billed tokens or
Raspberry Pi performance. Use the recorded command to reproduce the tool-only
benchmark; a future model-router experiment must report its own success, cost,
latency and escalation rate.

### Pre-merge cursor and flow corrections

The [September 7 qualification](semantic-cursor-2026-09-07.json) uses cursor
paging, preserving query/filter/detail/budgets while reusing the raw snapshot.
All 120 rows are verified. Cached calls measured 0.809 ms median / 1.032 ms p95
locally; the complete five-call observation measured 45.624 ms median. Fresh
capture varied substantially versus the earlier unpaired run, so this does not
establish a whole-workflow speedup. Descriptors are now 7,661 bytes and the table
results total 29,156 median bytes: cursor metadata has a cost, not free tokens.
The primary benefit is correct continuation with one input handle, plus stopping
flows on delayed popups and rejecting malformed stages before input. Model cost
and latency still require a separate controlled agent evaluation.
